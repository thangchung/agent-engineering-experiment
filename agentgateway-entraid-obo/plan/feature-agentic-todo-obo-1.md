# Introduction

![Status: Completed](https://img.shields.io/badge/status-Completed-brightgreen)

Executable implementation plan for the system specified in `prd.md` and `arch.md`. Three .NET 10 services (TodoApi, TodoAgent, TodoMcpServer) behind an **agentgateway v1.4.0-beta.1** (upgraded from alpha.2, 2026-07-27) mesh, chaining two On-Behalf-Of exchanges: hop-1 in the gateway (`backendAuth.oauthTokenExchange`), hop-2 in .NET via Microsoft Entra **Agent ID**. TodoAgent generates a todo `description` with a real `IChatClient` (Foundry Azure OpenAI via the gateway `/v1` route) and persists via an MCP `create_todo` tool that owns EF Core/SQLite. Architecture = Hexagonal (Ports & Adapters) + Vertical Slice. All alpha.2 capabilities are source-verified (see prd §7) and confirmed unchanged on beta.1 (route-matching source diff, TASK-059); RISK-001 (end-to-end Entra round-trip) is proven live (Phase 9).

Solution root: `/Users/chungt02/source_codes/oss/agent-engineering-experiment/agentgateway-entraid-obo`. Solution name: `AgenticTodo`. Reference codebase for reusable assets: `/Users/chungt02/source_codes/oss/agent-engineering-experiment/loop-runtime`.

## 1. Requirements & Constraints

- **REQ-001**: Human calls `GET /todos` and `POST /todos {name}` directly (no UI) through the gateway ingress with `Authorization: Bearer <userToken>` (`aud=api://<TodoApi>`, scope `access_as_user`).
- **REQ-002**: Hop-1 (TodoApi→TodoAgent) OBO exchange performed in the gateway (`backendAuth.oauthTokenExchange`, `grantType: jwtBearer`, `requested_token_use=on_behalf_of`); a `.NET` OBO + `passthrough` fallback exists, selected by `Hop1:Mode = gateway | dotnet`.
- **REQ-003**: Hop-2 (TodoAgent→TodoMcpServer) OBO performed in .NET via `IAuthorizationHeaderProvider.CreateAuthorizationHeaderForUserAsync(scopes, options.WithAgentIdentity(agentId), principal)`.
- **REQ-004**: TodoAgent generates `description` from `name` using a real `IChatClient` (gateway provider → Foundry Azure OpenAI, OpenAI-compatible `/v1`); no fakes in production path.
- **REQ-005**: TodoMcpServer owns EF Core/SQLite and exposes MCP tools `create_todo(name, description, checked=false)` and `list_todos()`; `Todo { Id, Name, Description, Checked, OwnerObjectId }`.
- **REQ-006**: Full mesh — every hop transits the gateway (human→TodoApi, TodoApi→TodoAgent, TodoAgent→Foundry, TodoAgent→TodoMcpServer).
- **REQ-007**: All our-own-API scopes use `access_as_user`; never `.default`.
- **REQ-008**: TodoApi exposes an OpenAPI document (`/openapi/v1.json`) + Swagger UI with an OAuth2 security scheme.
- **SEC-001**: Validate the JWT at every gateway route (`jwtAuth`/`mcpAuthentication`, mode strict, audience-pinned) AND in-service (`AddMicrosoftIdentityWebApi`).
- **SEC-002**: `OwnerObjectId` derived from the validated token `oid` (`ClaimsPrincipal.GetObjectId()`), never from the request body.
- **SEC-003**: TodoAgent Blueprint credential = client secret in local dev (`SourceType=ClientSecret`), FIC in prod (`SourceType=SignedAssertionFilePath`); config-swap only.
- **SEC-004**: Foundry endpoint/deployment/key live only in the gateway (env `AZURE_OPENAI_ENDPOINT|DEPLOYMENT|API_KEY`); the agent never holds the key. TodoApi client secret lives only in the gateway config.
- **SEC-005**: The `/mcp` gateway route uses `mcpAuthentication` ONLY — do NOT stack a route-level `jwtAuth` (agentgateway `mcp/auth.rs:34-42` rejects a pre-validated/stripped token).
- **CON-001**: Use the published gateway image `cr.agentgateway.dev/agentgateway:v1.4.0-alpha.2` (no local build).
- **CON-002**: .NET 10; single Entra tenant `768437b2-e373-41b5-9748-875e1507d85b`.
- **CON-003**: Foundry Azure OpenAI configured via environment variables (values supplied by operator).
- **CON-004**: Register all apps with `accessTokenAcceptedVersion = 2` (v2.0 tokens; issuer `.../v2.0`).
- **CON-005**: Entra Agent ID exchange uses `client_credentials` + `fmi_path` internally (NOT RFC 8693 → `AADSTS82001`); resource scope stays `access_as_user`.
- **GUD-001**: Architecture = Hexagonal (Ports & Adapters) per service + Vertical Slice (`Features/<Name>/` colocated endpoint+handler+DTO).
- **GUD-002**: Reuse loop-runtime `ServiceDefaults`, `ChatClientProvider`, FIC issuer as-is; adapt the Entra setup scripts to this 3-app todo domain.
- **GUD-003**: Domain core is I/O-free (no `Microsoft.Identity.*`, `EntityFrameworkCore`, `System.Net.Http`, `ModelContextProtocol`); enforce with a CI dependency test.
- **PAT-001**: Ports = C# interfaces; adapters depend inward only; bind in the composition root (`Program.cs`).
- **PAT-002**: MCP tool = inbound adapter over a repository port (`ITodoRepository`).
- **PAT-003**: Config-swap for hop-1 location via `IAgentGateway` implementations (`PassthroughAgentGateway` vs `OboAgentGateway`).

## 3. Alternatives

- **ALT-001**: Hop-1 OBO in TodoApi (.NET) with gateway `passthrough` — retained as the fallback (`Hop1:Mode=dotnet`), not the default; gateway exchange keeps TodoApi thin.
- **ALT-002**: TodoMcpServer performs description generation and TodoAgent owns persistence — rejected; TodoMcpServer-owns-EF/SQLite makes hop-2 a meaningful protected resource (prd ADR-005).
- **ALT-003**: TodoAgent calls Foundry via the Azure SDK directly — rejected; routing LLM through the gateway keeps the key off the agent and uniform (prd ADR-006).
- **ALT-004**: FIC for local dev via tunneled issuer — deferred; client secret on the Blueprint is simpler locally (prd R-2), FIC in prod.
- **ALT-005**: TodoAgent calls TodoMcpServer directly (bypass gateway) — rejected; violates the full-mesh requirement (REQ-006). MCP-through-gateway is source-verified to forward the bearer (prd PRV-1).

## 7. Risks & Assumptions

- **RISK-001** (CLOSED, proven in Phase 9 TASK-042/043): Full end-to-end OBO chain on agentgateway alpha.2 is now proven live — `GET /todos` through the complete public path returns `200 []` with a real captured JWT. 4 real gateway.yaml bugs found+fixed along the way (TASK-044a/b/c), none hop-2/client-secret related; `Hop1:Mode=dotnet` fallback was never needed.
- **RISK-002**: Microsoft Agent Framework / MCP C# SDK API names (`AsAIAgent`, `RunAsync`, MCP tool→AIFunction, `McpClient.CreateAsync`) may differ from the indicative code. Mitigation: verify against installed `Microsoft.Agents.AI` + `ModelContextProtocol` before compiling (CON, TASK-025/026).
- **RISK-003**: Agent ID permission-propagation delay (30–120 s) causes transient `403`/`AADSTS65001`. Mitigation: exponential-backoff retry after consent (TASK-010).
- **RISK-004**: agentgateway alpha.2 `llm` block field names may differ from `endpoint`/`deployment`. Mitigation: standalone config-load check (TASK-017) before wiring.
- **RISK-005**: Aspire container↔host networking (`host.docker.internal`, port publishing) misconfiguration blocks the gateway reaching host projects. Mitigation: TASK-033/034 explicit verification.
- **RISK-006** (verified in Phase 3, TASK-017c): agentgateway fetches JWKS eagerly/synchronously at startup for every `jwtAuth`/`mcpAuthentication` policy — an unreachable or tenant-not-found JWKS URL on **any single route** fails the **entire gateway process**, not just that route. Once Phase 2's script runs and real Entra IDs replace the `common`/placeholder defaults, verify the real tenant's JWKS resolves before relying on `aspire start` succeeding as a health signal.
- **RISK-007** (found in Phase 8, TASK-042b): `dotnet test AgenticTodo.slnx` (no flags) runs test *projects* in parallel by default; TASK-039's and TASK-040's live suites each independently boot the mesh via `aspire run`, and since every AppHost port is fixed (not dynamic, by design — see FILE-005), two concurrent boots collide. Mitigation: run `dotnet test AgenticTodo.slnx -m:1` when both heavy suites are enabled together.
- **ASSUMPTION-001**: Agent ID preview is enabled in tenant `768437b2-...` and the setup principal holds the required Graph roles (prd R-1).
- **ASSUMPTION-002**: A Foundry Azure OpenAI resource + chat deployment exist; the operator supplies endpoint/deployment/key via env (CON-003).
- **ASSUMPTION-003**: Single tenant for all apps + the agent (no cross-tenant; prd R-4).
- **ASSUMPTION-004**: loop-runtime reusable assets (`ServiceDefaults`, `ChatClientProvider`, FIC issuer, `UseScopedOidcFicSignedAssertionProvider`) are compatible with net10 as-is (GUD-002).
